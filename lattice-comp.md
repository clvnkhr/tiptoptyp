# Lattice comparison and ideas for tiptoptyp

Recorded **8 November 2026** for future product and implementation work.

Lattice is ahead in research, collaboration, and review workflows. tiptoptyp's
strongest advantages are Typst support, bundled local tools, controlled
formatting and diagnostics, and bounded local AI actions. Keep our core
architecture and adopt the workflow ideas that improve writing and reviewing.

## Scope and evidence

- Lattice source: [leo1oel/lattice](https://github.com/leo1oel/lattice), pinned to
  [`ff03b3727946cd2f9b13346529c49cad1a07f082`](https://github.com/leo1oel/lattice/tree/ff03b3727946cd2f9b13346529c49cad1a07f082)
  (7 November 2026, package version 0.15.7).
- tiptoptyp baseline: repository HEAD `a096fa6e94f6` plus the existing working-tree
  changes reviewed before the workspace persistence/offline work requested on
  8 November. This is a comparison snapshot, not a continuously updated feature
  inventory. Recommendations below are proposals, not completed implementation
  claims.
- Evidence is source inspection. Lattice was not built or launched, its live
  Overleaf compatibility was not tested, and the apps were not benchmarked
  against one another. “Better” below means better for the stated capability or
  design constraint; it does not establish overall reliability, speed, or
  security superiority.
- Links into Lattice use the pinned commit. tiptoptyp links point to this tree
  and can change as implementation proceeds. “Not found” means no equivalent was
  found in the inspected source, not proof that an undocumented feature cannot
  exist.

## Grammar, local AI, and reviewing suggestions

| Feature | Lattice implementation | tiptoptyp implementation | Assessment and recommendation |
| --- | --- | --- | --- |
| Background grammar checking | Runs Rust Harper in the background with reusable dictionary/linter state, structural prose masking, and serialized IPC jobs. Above 120,000 UTF-16 units it checks a visible window with a 2,000-unit margin; masks at window edges are approximate. [Backend](https://github.com/leo1oel/lattice/blob/ff03b3727946cd2f9b13346529c49cad1a07f082/src-tauri/src/harper.rs), [editor integration](https://github.com/leo1oel/lattice/blob/ff03b3727946cd2f9b13346529c49cad1a07f082/src/editor/harper-spellcheck.ts) | Independent Harper/LTeX+ providers, structural Typst/TeX prose parsing, bounded semantic paragraph cache, suppression markers, and stale-work protection. Harper job failures retain previous results. [Writing controller](src/app/writing.rs), [cache](src/writing/cache.rs), [LTeX+](src/app/ltex.rs) | Both have real background grammar checking. Preserve our structural/cache/error behavior; Lattice's viewport window is a scaling idea to measure, not a reason to introduce approximate masking. In the inspected frontend, a caught Harper failure returns an empty result list. |
| Grammar exceptions and dictionaries | Project word/rule/sentence ignores plus global profiles/dialects. [Quick actions and queue](https://github.com/leo1oel/lattice/blob/ff03b3727946cd2f9b13346529c49cad1a07f082/src/editor/harper-spellcheck.ts), [project model](https://github.com/leo1oel/lattice/blob/ff03b3727946cd2f9b13346529c49cad1a07f082/src-tauri/src/models.rs), [profiles](https://github.com/leo1oel/lattice/blob/ff03b3727946cd2f9b13346529c49cad1a07f082/src/editor/grammar-settings-store.ts) | Global dictionary/rule/name filters and region controls; no equivalent project exception overlay was found. Defaults are Harper off and LTeX+ on, with saved user preferences preserved. [Settings](src/settings.rs), [writing](src/writing.rs), [LTeX+ settings](src/ltex/settings.rs) | Lattice is better at keeping domain vocabulary local to a paper. Add a project dictionary/rule/sentence overlay, with clear scope in quick actions and settings. Do not let project overrides silently erase global choices. |
| General AI integration | Synara runs as an on-demand Node sidecar and integrates provider CLIs/tools and broader multi-file agent workflows. Inference location depends on the selected provider. [Host](https://github.com/leo1oel/lattice/blob/ff03b3727946cd2f9b13346529c49cad1a07f082/src-tauri/src/synara.rs), [runtime](https://github.com/leo1oel/lattice/blob/ff03b3727946cd2f9b13346529c49cad1a07f082/docs/synara-runtime.md) | Local ONNX Liquid selection correction plus bounded LFM3 diagnostic fixes: one diagnostic, constrained context/JSON, no model tools, explicit diff acceptance. A terminal can run CLIs but is not an integrated general agent host. [Diagnostic fix](src/diagnostic_fix.rs), [selection review](src/app/liquid.rs) | Lattice wins on breadth; ours is simpler and locally bounded for precise corrections. Keep the focused right-click fix workflow. Treat a general agent host as a separate product decision with explicit project/tool access, cancellation, and review. |
| Proofread/polish review granularity | Proofread, Polish, and custom modes produce logical edits with categories/reasons and per-edit toggles. Polish is not remembered as the default; LaTeX protection is checked. One request is limited to 12,000 characters. [Modes](https://github.com/leo1oel/lattice/blob/ff03b3727946cd2f9b13346529c49cad1a07f082/src/agent/agent-proofread.ts), [edits](https://github.com/leo1oel/lattice/blob/ff03b3727946cd2f9b13346529c49cad1a07f082/src/agent/proofread-edits.ts) | Selection corrections are locally chunked up to 1 MiB and reviewed as a whole selection; diagnostic fixes have their own diff review. [Liquid review](src/app/liquid.rs), [diagnostic review](src/app/diagnostic_fix.rs) | Borrow per-edit accept/reject and clearly separate correction from rewriting. Keep our local model and larger bounded/chunked path. A tagger's output does not automatically provide trustworthy natural-language reasons; do not invent them. |
| Keeping a review valid while editing | Rebases selected spans, checks original text and a combined LaTeX signature, and applies accepted edits as one undoable action. [Anchor](https://github.com/leo1oel/lattice/blob/ff03b3727946cd2f9b13346529c49cad1a07f082/src/editor/proofread-anchor.ts), [application guards](https://github.com/leo1oel/lattice/blob/ff03b3727946cd2f9b13346529c49cad1a07f082/src/canvas/proofread-layer.tsx) | Any relevant revision/source change invalidates the pending selection or diagnostic review; acceptance is guarded and undoable. [Selection guards](src/app/liquid.rs), [diagnostic guards](src/app/diagnostic_fix.rs) | Lattice is more convenient for long-running selected-prose reviews. Consider conservative span rebasing only for that case. Keep stricter revision guards for diagnostic fixes: an edit elsewhere may change whether an LSP diagnosis or proposed replacement is still valid. |

| Local external-edit reconciliation | Uses diffy's three-way merge for editor-versus-disk changes; overlapping edits can write conflict markers. [Save I/O](src/save_io.rs), [save controller](src/app/saves.rs), [existing merge](src/overleaf/model/merge.rs) | Borrow automatic merging of independent edits, reusing our bounded merge core where possible. | Local history and project revisions | Actor-owned semantic project transactions, 45-second coalescing, and a unified local/Git/Overleaf timeline. ## Suggested implementation order

### 1. Reliability and recovery

1. **Durable Overleaf workspace links and offline mode.** Remember project URL,
   local-storage identity, account/profile identity, and last synchronized file
   baselines. On reopen, immediately show the retained local files, restore the
   appropriate browser session, refresh remote state, and reconcile before
   publishing. Merge independent edits; review overlapping text edits and
   delete/modify or binary conflicts. A network/login failure must leave local
   work available and must not overwrite the server or discard unsent work.
   Keep profile credentials browser-owned; persisting a profile identity does
   not require exporting its cookies. Respect normal server-side session expiry.
2. **External dependency rebuilds.** Coalesce meaningful project changes,
   invalidate the affected root, exclude generated outputs and own writes, and
   preserve bounded background work.
3. **Three-way local save reconciliation.** Reuse our conservative merge core
   for nonoverlapping disk/editor changes, with explicit overlap review and
   revision-bound application.
4. **latexdiff safety.** Add input-cycle preflight and process memory bounds,
   then project/Git version selection without increasing wizard page count.

### 2. Everyday editing and navigation

1. Audit accessibility in the real app, then add the missing semantics and
   interactions. Source inspection alone cannot establish VoiceOver usability.
2. Add per-match PDF navigation, search options, and cross-page selection while
   retaining bounded loading/rendering and current-artifact identity.
3. Add TexLab Go to Definition and root-directive inference, retaining explicit
   user choices as the highest priority.
4. Improve SyncTeX word/bibliography landing without making navigation save or
   compile source.
5. Add project-scoped grammar exceptions; preserve provider-independent comment
   controls, structural parsing, and saved preference choices.

### 3. Review and research

1. Add per-edit acceptance for Liquid selection corrections and a clearly
   distinct rewriting mode only if a suitable model supports it.
2. Allow conservative selected-prose review rebasing. Keep diagnostic fixes
   strict when surrounding context changes.
3. Add deterministic reference checks, then provenance-backed optional online
   audit and a BibTeX-authoritative local paper library.
4. Add persistent source/PDF notes, replies, revision rounds, and standard PDF
   comment export; then native Overleaf conversation/tracked-change review.
5. Add reproducible project snapshots and unified version selection, clearly
   labeling historical files that are rendered against current dependencies.

### 4. Delivery and measured optimization

1. Add signed/notarized releases and signed in-app updates with coordinated
   saving and a user-controlled restart.
2. Add deterministic performance budgets to CI; use comparable native workloads
   for latency, CPU, memory, and preview-composition claims.
3. Prototype a narrowly scoped preamble cache only after recording a matched
   baseline and defining invalidation/PDF/SyncTeX parity checks.
4. Consider named layout presets and settled terminal resizing when needed.
   Defer general canvas breadth and a general AI host until there is a concrete
   product need.

## Constraints to retain while learning from Lattice

- Keep empty startup/workspaces and explicit **File → Make Demo File** behavior.
- Keep useful concise UI copy; do not add login “unlock” instructions or other
  status text that does not help the user take a meaningful action.
- Keep one-page latexdiff creation, automatic selected-compiler PDF generation,
  visible completion/failure feedback, and no-clobber file creation.
- Keep local AI installation explicit, inference bounded and cancellable, and
  source changes reviewable/undoable. A broad agent must not become a
  prerequisite for ordinary editing, Git, or diagnostics.
- Keep custom formatting/diagnostic markers, whitespace-tolerant parsing,
  structural exclusions, and saved user preferences.
- Keep workspace document ownership separate from layout arrangements and
  account identity. Switching workspaces must close old-workspace file pages
  safely and must not leak one workspace's session or unsaved work into another.
- Keep existing stale-session/receipt/epoch guards and bounded workers. A local
  mirror is only a valid synchronization ancestor after confirmed remote state,
  not merely because a write reached the local disk.
